# Backend

The storefront stays a static site. Alongside it sit three functions, a
Postgres database and Razorpay. Nothing about the build changed: `dist/` is
still generated by `node build.mjs` and still deploys as files.

```
dist/                      the site, as before
api/checkout.js            price a cart, open a Razorpay order, record ours
api/razorpay-webhook.js    the only thing that marks an order paid
api/stock.js               live quantities for the shop
api/_lib/                  pricing, database, Razorpay, request plumbing
db/schema.sql              tables
db/seed-stock.mjs          fill the stock table from the catalogue
```

## The one rule

**The browser is never believed about money.** It sends product, size and
quantity. Prices come from `src/data.mjs`, stock from the database, shipping
from the rule in `api/_lib/pricing.mjs`, and the total is computed on the
server every time. A cart that claims lavender costs ₹1 is charged ₹699.
There is a test for exactly this.

Money is integer paise everywhere — in the code, in the database, and in what
Razorpay is told. Rupees as decimals round badly, and these are real charges.

## What settles an order

A browser returning from the payment screen proves nothing: it can close, or
lie. Orders become `paid` only in the webhook, which is signed by Razorpay and
verified against the raw request bytes.

The webhook is built to be delivered twice, because Razorpay retries. Only an
order still at `created` moves, so a repeat delivery changes nothing and
stock cannot be decremented twice.

## Setup

1. **Database.** Create a Postgres database (Neon's free tier is enough), then:

   ```bash
   psql "$DATABASE_URL" -f db/schema.sql
   npm run seed
   ```

2. **Razorpay.** Sign up, stay in **Test mode**, and take the key id and
   secret from Settings → API Keys.

3. **Environment.** `cp .env.example .env.local` and fill it in. Never commit
   it; `.env*` is already gitignored.

4. **Webhook.** Settings → Webhooks → add
   `https://<your-domain>/api/razorpay-webhook`, subscribe to
   `payment.captured` and `payment.failed`, and set the secret to the same
   string as `RAZORPAY_WEBHOOK_SECRET`.

   A webhook cannot reach `localhost`. To test locally, tunnel (`ngrok http
   3000`) and point the webhook at the tunnel.

5. **Deploy.** Vercel, importing the repo. `vercel.json` already declares the
   build and the functions. Add the same environment variables there.

## Testing payments

In test mode, card `4111 1111 1111 1111`, any future expiry, any CVV. No money
moves. Verify an order reaches `paid` and that stock went down:

```sql
select id, status, total_paise, created_at from orders order by created_at desc limit 5;
select sku, quantity from stock where quantity < 10;
```

## Known trade-offs

**Stock is not reserved between checkout and payment.** Two shoppers can both
pass the stock check on the last bottle; the second to pay is caught by the
`quantity >= qty` guard and their order is marked `oversold` rather than
silently shipped. That is deliberate: reserving stock at checkout would let
abandoned carts hold inventory hostage, which at this volume is the more
common and more costly failure. If orders start colliding, add a reservation
with an expiry.

**No admin screen yet.** Orders are read with SQL. That is honest for the
first weeks and gets old quickly.

**No order confirmation email yet.** The order is recorded; nobody is told.
This is the first gap worth closing.

## Before taking real money

These are not optional, and two of them are legal requirements in India:

- **Policy pages.** Privacy Policy, Terms, Refund/Cancellation and Shipping
  Policy. Required by the Consumer Protection (E-Commerce) Rules 2020, and
  Razorpay will not activate a live account without them. The site has none.
- **Business verification.** Razorpay needs PAN, bank account and, above a
  threshold, GST registration.
- **Switch the keys.** `rzp_test_…` to `rzp_live_…`, and a fresh webhook
  secret. `isTestMode()` in `api/_lib/razorpay.mjs` reports which is in use.
- **Confirm the shipping fee.** `site.shippingFlat` is set to ₹79 below the
  ₹999 free-shipping threshold. That number was chosen as a placeholder — the
  site had never stated a fee — and should be a decision, not an inheritance.
